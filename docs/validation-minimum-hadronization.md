# HADROTYPE=1 Pythia8 export and native runner

The native hadronized runner now accepts `--hadrotype 0|1`. Mode 0 remains the
default. Mode 1 uses the [Fortran-validated minimum-string constructor](validation-minimum-strings.md)
and exports its ordered strings to Pythia8 with new colour tags. It does not
invoke Pythia8 colour reconnection.

```sh
build-pythia8/jewel-run-events minimum.jsonl 20 2601001 medium --hadrotype 1
ctest --test-dir build-pythia8 -R '^(runner-hadrotype-contracts|pythia8-minimum-output-contracts|pythia8-shower-output-contracts|strings-contracts)$' --output-on-failure
```

## Adapter semantics

Each ordered string begins with an endpoint, continues through zero or more
gluons and terminates at an oppositely coloured endpoint. The adapter gives each
link a fresh colour tag, including the reversed orientation for antiquarks and
the appropriate opposite colour representation for diquarks. Malformed or
unterminated strings fail explicitly. Copied colourless particles carry no tags.
Native parent IDs are mapped to physical input slots before invoking MINL.

Two native/Pythia8 boundary treatments are explicit:

1. A native status-0, PDG-0, zero-momentum/zero-colour padding row is marked
   inert before construction. It is not a physical Fortran PYJETS particle and
   must not become a zero-energy hadronization input.
2. For quark halves generated by splitting a gluon, the copied parent mass field
   is multiplied by the same fraction as the daughter's four-momentum. Literal
   MINL retains the unscaled parent P(5), which is inconsistent for a massive
   parent and fails Pythia8's input check. Four-momenta are unchanged by this
   adapter correction. The literal Fortran-boundary port remains unchanged.

The header's `minimum_string_policy` records these mode's ID/mass conventions,
endpoint energy and rapidity settings. Input IDs are local ordered-string IDs;
`hadronization_native_sources` is a parallel array of original stable native IDs,
with null for artificial endpoints. Split quark halves share their original
gluon's source ID. Source-backed particles inherit native production coordinates
(converted fm to mm); artificial endpoints use zero vertex coordinates.

The constructor continues the existing per-event random stream. `draws` retains
the pre-string cascade count and `string_draws` reports the additional draws.
The sum gives the consumed stream length after string construction. Failed
attempts retain the existing failure-stage and draw-count reporting.

## Validation

Actual Pythia8 hadronization contracts pass for quarks, antiquarks, diquarks,
antidiquarks and split gluons, including a massive gluon. Tests check balanced
colour, distinct output IDs, provenance, artificial endpoint momentum, correct
mass scaling and preservation of the original native state.

Runner tests confirm mode dispatch, invalid-option rejection, identical default
versus explicit mode-0 output, and unchanged cascade particles/initial hard legs/
thermal references/draw counts when switching the same event to mode 1. All four
selected contract suites pass.

The final-build samples at seed 2601001 give:

| Setting | Accepted / attempts | Synthetic endpoints | Generated quark halves | Maximum hadronization closure error, GeV |
|---|---:|---:|---:|---:|
| Vacuum | 20 / 20 | 32 | 34 | 7.39e-13 |
| Medium | 18 / 20 | 36 | 66 | 4.55e-13 |

The two medium failures are existing cascade nonfinite-kinematics failures;
there are no string or hadronization failures in these samples. The audit checks
all input tags, every native/synthetic association and split momentum/mass
fraction, and final hadron momentum closure. [Executable and input hashes, counts and failures](validation-minimum-hadronization.json).

Closure is measured against the **supplied string input**. MINL intentionally
adds 10 GeV endpoints when partners are missing and removes partons outside its
rapidity domain; it does not conserve the complete pre-string event momentum.
These source behaviors remain visible rather than being silently compensated.

This enables the native mode, but does not establish Pythia6/Pythia8 hadron-level
parity or the requested matched jet-spectrum/substructure ratios. The generated
quark mass-field adaptation is an explicit compatibility choice requiring that
later physics comparison.
